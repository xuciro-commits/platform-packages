# CRM 设计稿

## 一句话

销售的一天从“下一步”开始。每条新线索有首次响应时限，每个进行中的商机都有下一步与到期日；
打开 CRM 先看到今天该做的事，而不是一张空表单。录入只是推进的副产品。

## 我们从成熟产品里看到的套路

成熟 CRM 的骨架大同小异，好产品赢在几处交互纪律。我们读的是这些套路，不是哪一家的定义。

| 套路 | 在哪里看到 | 我们怎样做 |
|---|---|---|
| 线索与商机分两段，中间有资格判断 | Frappe CRM、Odoo、Salesforce | 线索只回答“值不值得跟”；转成商机时一次建好公司、联系人与商机，已有的按名称与邮箱匹配 |
| 阶段与结果分开 | Salesforce、Pipedrive | 商机的阶段（资格、需求、方案、谈判、承诺）只描述进行中的位置；赢单与丢单是动作，带必填信息，不是看板上的一列 |
| 活动驱动：每个商机必须有下一步 | Pipedrive | 进行中的商机必填“下一步”和到期日；到期进负责人的收件箱，过期提醒；没有下一步的商机在视图里一眼可见 |
| 首次响应时限与公平分配 | Frappe CRM、HubSpot | 新线索按负责人负载均衡分配；默认 4 小时内首次响应，超时通知负责人与销售经理 |
| 加权金额与预测类别 | Salesforce | 阶段字典带概率与预测类别（管道、可能、承诺）；商机算加权金额；仪表盘按预测类别汇总 |
| 商机里的人有角色 | Salesforce | 商机关联多位联系人，各有角色（决策人、推动者、影响者、使用者、阻碍者） |
| 一条时间线 | HubSpot、Twenty | 记录页的活动里有评论、状态变化、备注与任务；任务和备注可挂到线索、商机、公司或联系人 |
| 结构化的赢单与丢单 | 各家 | 丢单原因与竞争对手是字典，赢单写入成交日与最终金额，公司随之变成客户；仪表盘看赢率与丢单原因 |

Frappe CRM 把 Won、Lost 放在状态字典里，与进行中的状态混在一个字段，要靠约束防止随手改成 Won。
我们把生命周期（进行中、赢单、丢单）交给平台的状态与动作，阶段只是进行中的子位置，这类约束就不需要了。

## 对象

| 对象 | 是什么 | 关键字段 |
|---|---|---|
| 线索 `crm.lead` | 还没判断的一个人或一次询盘 | 姓名、公司名、职务、邮箱、手机、来源、行业、地区、负责人、跟进阶段；资格四问：需求、预算、时间、决策权；首次响应时限与结果 |
| 公司 `crm.account` | 我们打交道的组织 | 名称、网站、行业、地区、规模、年营业额、负责人、关系（潜在、客户、合作伙伴、前客户）；进行中管道与累计赢单（汇总） |
| 联系人 `crm.contact` | 公司里的人 | 姓名、公司、职务、邮箱、手机、电话、领英、负责人、请勿联系 |
| 商机 `crm.deal` | 一次有望成交的机会 | 名称、公司、主要联系人、负责人、阶段、金额、概率、加权金额、预测类别、预计成交、下一步、下一步到期、来源线索、来源、竞争对手；结果：成交日、丢单原因、说明 |
| 商机联系人 `crm.dealcontact` | 商机里的一位联系人与他的角色 | 商机、联系人、角色、备注 |
| 商机产品 `crm.dealline` | 商机报价里的一行 | 商机、产品、数量、单价、折扣、金额（公式） |
| 产品 `crm.product` | 可报价的产品或服务 | 编码、名称、类别、标准单价、启用 |
| 活动 `crm.activity` | 要做或做过的一件事 | 类型（电话、会议、邮件、演示、待办）、主题、到期、负责人、状态、优先级、结果；挂到线索、商机、公司或联系人之一 |
| 备注 `crm.note` | 记下来的信息 | 标题、内容、置顶；挂到线索、商机、公司或联系人之一 |

字典（参考记录随包安装，租户可增改）：商机阶段 `crm.stage`（顺序、颜色、概率、预测类别）、线索来源 `crm.source`、
行业 `crm.industry`、地区 `crm.territory`（可嵌套）、丢单原因 `crm.lostreason`、不合格原因 `crm.disqualifyreason`、竞争对手 `crm.competitor`。

## 生命周期与动作

线索：`open → converted | disqualified`，`disqualified → open`（重新打开）。
进行中的跟进阶段：新建 → 尝试联系 → 已联系 → 培育中，看板按它分列，拖动即改。

| 动作 | 从 | 做什么 |
|---|---|---|
| 转为商机 | open | 先要填了预算（它就是商机金额，也逼着把资格问清）。一次事务：已有客户就关联（同名的预填供选），否则按公司名新建；联系人同理按邮箱；新建商机，阶段“资格”，必填预计成交、下一步与到期；建一条商机联系人，决策权是决策人就记为决策人，否则记为推动者；线索标为已转化并指向商机；打开商机 |
| 判为不合格 | open | 必填原因，可写说明 |
| 重新打开 | disqualified | 回到进行中 |

商机：`open → won | lost`，`won | lost → open`。

| 动作 | 从 | 做什么 |
|---|---|---|
| 赢单 | open | 成交日默认今天，可写“赢在哪里”；客户关系改为成交客户。最终金额在赢单前直接改金额字段 |
| 丢单 | open | 必填丢单原因，可选竞争对手与说明；成交日写今天 |
| 重新打开 | won、lost | 回到进行中；必须重新给下一步与到期 |
| 完成、取消、重新打开活动 | 活动 | 活动有自己的状态：待办 → 完成（写结果）或取消；完成后可重新打开 |

## 角色与可见性

| 角色 | 线索、商机、活动、备注 | 公司、联系人 | 字典与产品 |
|---|---|---|---|
| 销售 `salesrep` | 读本单元，建、改；不能归档 | 读全部，建、改 | 只读 |
| 销售经理 `salesmanager` | 读全部，建、改、归档 | 读全部，建、改、归档 | 增改 |

负责人默认是创建者。销售经理是团队的上级；“本单元”按组织单元划，上级看下级由平台的单元树决定。

## 页面与导航

- 菜单按一天的工作排：销售（仪表盘、线索、商机）→ 客户（客户、联系人）→ 跟进（活动、备注）→ 资料（产品、竞争对手）→ 设置（只给经理：阶段、来源、行业、地区、丢单原因、不合格原因）。设置是一页，每个字典一张可就地改的表，阶段可上下移动。
- 每个对象有自己的图标（线索 user-plus、商机 briefcase、客户 building-office-2、联系人 identification、活动 calendar-days……），同一应用里不重复。
- 列表的默认样子按用途：线索按响应时限排的表格（可切到按跟进阶段的看板）；商机按阶段的看板；客户按名称的表格（可按关系分列）；
  联系人按客户分组；活动默认日历；备注置顶在前。
- 收件箱的“待办”：我负责且到期不晚于今天的活动、商机的下一步、未响应的新线索。

## 自动化

| 流程 | 触发 | 效果 |
|---|---|---|
| 分配新线索 | 新线索没有负责人 | 取销售里进行中线索最少的人 |
| 首次响应时限 | 线索进入进行中 | 到期时仍是“新建”，标为超时并通知负责人 |
| 记下首次响应 | 线索离开“新建” | 写首次响应时间，按时限判定达成或超时 |
| 下一步过期 | 商机下一步到期 | 到期仍进行中且下一步未改，通知负责人 |

## 仪表盘

进行中管道金额、加权预测、本期赢单金额、赢率；按阶段的漏斗；按负责人的管道；按预测类别的管道；线索来源占比；
每月新线索与每月赢单金额；丢单原因占比。

## 受平台限制的取舍

- 动作参数还没有金额类型，所以转商机不单独问金额（取预算），赢单不单独问最终金额（先改金额字段）。平台补上后改回。
- 首次响应只记“达成 / 超时”，不记时刻：流程步骤的输入还不能取“现在”。
- 下一步与到期对所有商机必填，不只进行中的：事务新建步骤里还不能按状态判断字段。关闭的商机保留最后一个下一步，不影响使用。

## 这一版不做

邮件与通话的同步、报价单打印、网页表单、资料富集、多币种汇率、按地区授权、营销活动。它们需要连接器或平台能力，之后各自成包或成版本。

## 验收

在夹具宿主装进空租户：经理配角色；销售新建线索并在时限内联系、填资格四问、转为商机；商机加联系人角色与产品行；
推进阶段、更新下一步；赢单后公司变客户、仪表盘数字对得上；另一个商机丢单，原因进占比；销售看不到别的单元的商机。
