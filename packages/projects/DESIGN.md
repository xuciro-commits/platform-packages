# 项目设计稿

## 一句话

项目经理的一天从“哪些任务拖了、谁的活太多”开始，成员的一天从“今天该做什么、昨天记了几小时”开始。
打开项目，经理先看到甘特上落后的任务与各项目的进度和工时，成员先看到收件箱里到期的任务和本周还没记的工时。

## 我们从成熟产品里看到的套路

| 套路 | 在哪里看到 | 我们怎样做 |
|---|---|---|
| 项目是任务的容器，进度由任务汇总 | ERPNext（Project 的 percent_complete 按任务）、OpenProject、Plane | 项目的进度、预计与实际工时都是汇总，不手填 |
| 任务有起止与前置，排在甘特上 | OpenProject（前置关系、甘特）、ERPNext（depends_on） | 任务有开始、结束与“在…之后”；列表默认甘特，拖动改日期 |
| 状态看板和生命周期分开 | Plane（Backlog/Todo/In Progress/Done 可配置）、OpenProject | 任务的阶段（待办、进行中、待验收）是可配置的字典，做完与取消是动作 |
| 工时挂在任务上，按人按天记 | Kimai（时间记录：日期、时长、活动、可计费）、ERPNext Timesheet | 一条工时记录：谁、哪天、哪个任务、几小时、活动类型、是否计费 |
| 计费与内部工时分开统计 | Kimai（billable）、ERPNext（billing hours） | 工时带“计费”，项目汇总计费工时，供后面的开票包使用 |
| 里程碑是没有长度的任务 | OpenProject（milestone 类型）、ERPNext | 任务上的“里程碑”开关；里程碑开始等于结束 |
| 客户项目挂客户 | ERPNext（project.customer）、Kimai（customer → project → activity） | 项目可选一个往来单位，客户只在往来单位存一份 |

各家的设计债，我们避开：

- ERPNext 的 Project 与 Task 各有一套 status，加上 Timesheet 的提交与作废，三套状态互相影响，进度常与实际对不上。
  我们的任务只有一套平台状态（进行中 / 已完成 / 已取消），阶段是看板上的列，进度只从任务算。
- ERPNext 的 Timesheet 是一张多行单据，一周的工时要在同一张单里填；Kimai 一条记录一次工作。我们照 Kimai，一条一笔，按周的视图由列表分组给出。
- OpenProject 的工作包类型、自定义字段与工作流组合很重，第一版只做项目、任务、工时三件事。

## 六个词

| 平台词 | 项目的答案 |
|---|---|
| 状态 | 项目 计划中 → 进行中 ⇄ 暂停，→ 已完成 / 已取消；任务 进行中 → 已完成 / 已取消，可重开 |
| 字典 | 任务阶段（顺序、颜色）、项目类型、活动类型（开发、设计、会议、支持……） |
| 动作 | 启动项目、暂停、恢复、完成项目（还有未完成任务时拒）；完成任务、取消任务、重开 |
| 派生 | 任务的实际工时（汇总工时）、剩余工时；项目的任务数、已完成数、进度 %、预计与实际工时、计费工时 |
| 角色与范围 | 成员读全部项目、读改本单元同事的任务、只读写自己的工时；经理读全部、建项目与任务、取消任务、管字典 |
| 注意力 | 到期未完成的任务进负责人收件箱；任务结束日过了仍未完成提醒；项目实际工时超过预计提醒经理 |

## 对象

| 对象 | 是什么 | 关键字段 |
|---|---|---|
| 项目 `projects.project` | 一件有起止的事 | 名称、类型、客户（`party.organization`，可选）、经理、开始、结束、预计工时、说明；任务数、完成数、进度 %、实际与计费工时（汇总） |
| 任务 `projects.task` | 项目里的一件活 | 项目、标题、负责人、阶段、开始、结束、在…之后（前置任务）、里程碑、预计工时、优先级、说明；实际与剩余工时（汇总） |
| 工时 `projects.timelog` | 一个人一天在一个任务上的时间 | 任务、项目（从任务带出）、成员、日期、小时、活动类型、计费、说明 |

字典（参考记录随包安装，经理可增改）：任务阶段 `projects.stage`、项目类型 `projects.projecttype`、活动类型 `projects.activity`。

## 角色与可见性

| 角色 | 项目 | 任务 | 工时 | 字典 |
|---|---|---|---|---|
| 成员 `member` | 读全部 | 读、建、改本单元同事的，完成、重开 | 读、建、改自己的 | 只读 |
| 经理 `manager` | 读全部，建、改、启动、暂停、完成、取消 | 读全部，建、改、指派、取消 | 读全部 | 增改 |

## 页面与导航

- 菜单：工作（我的任务、本周工时）→ 计划（项目、任务甘特）→ 设置（只给经理）。
- 任务默认甘特（开始、结束、在…之后），可切看板（按阶段）与表格；项目默认表格，带进度与工时列；工时按日期的表格、按成员分组。
- 收件箱：指给我、到期的任务。

## 自动化

| 流程 | 触发 | 效果 |
|---|---|---|
| 任务逾期提醒 | 任务结束日过了仍在进行中 | 提醒负责人 |
| 工时超预计 | 项目实际工时超过预计工时 | 提醒项目经理 |

## 仪表盘

进行中的项目数、本周工时、逾期任务数、本月计费工时；各项目进度；各成员本周工时；按活动类型的工时分布。

## 依赖与取舍

- 依赖 `party@^0.2.0`（客户）。不依赖 hr-core：负责人与成员是平台成员，不是员工档案。
- 任务的工作日按组织日历算（`workdays`），没有日历时按周一到周五。
- 前置关系只表达“在…之后”一条，排程不自动顺延；甘特上拖动由人决定。
- 计费只记标记与汇总，开票留给后面的销售与会计包。
- 平台的改与读同一个范围：成员能读的本单元任务也能改，做不到“只改指给自己的”；第一版接受。
- 进度是小数（完成数 × 100 ÷ 未取消任务数），平台表达式没有取整函数。

## 这一版不做

资源负荷与排程优化、关键路径、基线对比、子项目与任务层级、工时审批与锁定、按人的费率与成本、看板泳道的 WIP 限制、项目模板。

## 验收

在夹具宿主装进空租户：经理建项目与三个任务（第二个在第一个之后），甘特上看到三条；成员只看到本单元的任务，给自己的任务记两次工时，
任务与项目的实际工时随之变化；成员看不到别人的工时、不能取消任务；经理完成项目被拒（还有未完成任务），完成全部任务后项目完成、进度 100%。
