# 人事核心设计稿

## 一句话

员工的一天从“我还剩几天假、我的申请批了没有”开始，经理的一天从“谁在等我批”开始。
打开人事核心，员工先看到自己的余额与待办申请，经理先看到收件箱里等批的请假、补卡与报销，人事先看到今天谁不在。

## 我们从成熟产品里看到的套路

| 套路 | 在哪里看到 | 我们怎样做 |
|---|---|---|
| 额度与申请分开 | Frappe HRMS（Leave Allocation 与 Leave Application）、OrangeHRM（Entitlement 与 Leave Request） | 假期额度是一条记录（员工、假期类型、期间、天数）；申请指向额度，余额由已批与在批的申请汇总，不存快照 |
| 余额不够就不让提交 | HRMS、OrangeHRM | 申请提交时的条件：申请天数不超过额度的可用余额；不允许透支的假期类型直接拒，说清还剩几天 |
| 审批人是直属上级 | HRMS（部门审批人、员工的上级）、OrangeHRM（Supervisor）、Dolibarr（直属主管收到邮件） | 请假、补卡、报销都走平台审批，第一级是申请人所在单元的主管，进他的收件箱；人事可以代批 |
| 提交前可改，批了就锁 | Dolibarr（草稿、待批、已批、已付） | 草稿可改可删；提交后只能撤回；批准后只能由人事取消，取消把天数还回余额 |
| 报销的“批”和“付”是两件事、两个人 | Dolibarr（批准与标记已付是两个权限） | 经理批准，财务标记已付；行上有“核准金额”，经理可以少批 |
| 考勤是打卡的结果，例外走申请 | HRMS（Employee Checkin → Attendance，Attendance Request） | 员工当天上班、下班两次打卡生成当天考勤；忘打卡、外勤、居家走补卡申请，批准后改考勤 |
| 谁不在一眼可见 | OrangeHRM（Leave Calendar）、HRMS（Leave Calendar） | 请假列表默认日历，按日期铺开已批的假；仪表盘第一格是“今天请假的人” |
| 员工档案是一切的锚 | 各家 | 员工记录连着成员账号、部门、职位、上级与在职状态；申请默认带出申请人对应的员工 |

各家的设计债，我们避开：

- HRMS 的请假申请有两套生命周期：`status`（Open、Approved、Rejected、Cancelled）与单据的提交与作废，批准要先改状态再提交，两者对不上时很难解释。
  我们只有一套：平台状态加审批，批准就是一次动作。
- HRMS 在申请上存一份 `leave_balance` 快照，之后额度变了它不跟着变。我们的余额始终是汇总出来的。
- OrangeHRM 把请假的每一天存成一行，再用一张请求表把它们串起来，余额与列表都要跨两张表算。我们一条申请一个日期区间，部分撤销这一版不做。
- Dolibarr 把“已提交、等审批”叫“已验证”，用户常误以为已经批了。我们的状态名就是“待批”。

## 六个词

| 平台词 | 人事核心的答案 |
|---|---|
| 状态 | 员工 在职 / 离职；请假 草稿 → 待批 → 已批 / 已驳回，已批 → 已取消；补卡 同请假；报销 草稿 → 待批 → 已批 → 已付，待批 → 已驳回；考勤 进行中 → 已完成 |
| 字典 | 部门（可嵌套，带主管）、职位、用工类型、假期类型（是否带薪、能否透支、每次最多几天）、报销类型 |
| 动作 | 提交（走审批）、撤回、取消已批的假（还天数）；上班打卡、下班打卡；报销付款（财务）；离职（必填离职日期与原因） |
| 派生 | 请假天数（结束 − 开始 + 1，半天减 0.5）；额度的已用、在批与可用；报销行合计与核准合计；考勤工时 |
| 角色与范围 | 员工读自己的；经理读本单元同事的；人事读全部、管字典与额度；财务读全部报销并付款 |
| 注意力 | 审批进经理收件箱；草稿超过三天提醒；今天请假的人；本月报销待付 |

## 对象

| 对象 | 是什么 | 关键字段 |
|---|---|---|
| 员工 `hr.employee` | 一个在册的人 | 工号、姓名、成员账号、部门、职位、用工类型、上级、入职日期、手机、工作邮箱、紧急联系人；离职日期与原因 |
| 假期额度 `hr.allocation` | 一个员工在一个期间某类假的天数 | 员工、假期类型、起止日期、天数；已用、在批、可用（汇总） |
| 请假 `hr.leave` | 一次请假申请 | 员工、额度（带出假期类型）、开始、结束、半天、天数（派生）、事由 |
| 考勤 `hr.attendance` | 一个员工一天的出勤 | 员工、日期、上班、下班、工时（派生）、类型（出勤、外勤、居家）、迟到 |
| 补卡 `hr.correction` | 对某天考勤的更正申请 | 员工、日期、类型、上班、下班、说明 |
| 报销单 `hr.claim` | 一次报销 | 员工、事由、合计、核准合计（汇总）、付款日期 |
| 报销行 `hr.claimline` | 报销单里的一笔 | 报销单、日期、类型、金额、核准金额、说明、票据（附件） |

字典（参考记录随包安装）：部门 `hr.department`、职位 `hr.designation`、用工类型 `hr.employmenttype`、
假期类型 `hr.leavetype`、报销类型 `hr.expensetype`。

## 角色与可见性

| 角色 | 自己的员工档案 | 请假、补卡、报销、考勤 | 额度 | 字典 |
|---|---|---|---|---|
| 员工 `staff` | 读，改联系方式 | 读自己的，建、改草稿、提交、撤回 | 读自己的 | 只读 |
| 经理 `manager` | 读本单元同事的 | 读本单元同事的，审批 | 读本单元同事的 | 只读 |
| 人事 `hradmin` | 读全部，建、改、离职 | 读全部，代批、取消已批的假 | 建、改 | 增改 |
| 财务 `finance` | 只读 | 读全部报销，付款 | 无 | 报销类型 |

## 页面与导航

- 菜单按工作顺序：我的（我的假期、我的考勤、我的报销）→ 团队（待我审批、团队假期日历、团队考勤）→ 人员（员工、额度）→ 设置（只给人事）。
- 请假默认日历（按开始到结束铺开）；员工按部门分组；报销按状态看板；考勤按日期的表格。
- 收件箱：等我审批的申请；我的被驳回、待修改的申请。

## 自动化

| 流程 | 触发 | 效果 |
|---|---|---|
| 草稿提醒 | 请假或报销草稿创建三天后仍是草稿 | 提醒申请人 |
| 批准通知 | 请假、补卡、报销被批准或驳回 | 通知申请人 |
| 补卡生效 | 补卡被批准 | 新建或更新那一天的考勤 |

## 仪表盘

今天请假的人数与名单、待批申请数、本月请假天数、本月报销金额与待付金额；按部门的在职人数；按假期类型的已用天数。

## 平台缺口与取舍

接入时补进平台的（平台 v0.2.7）：审批级别 `manager: true` 交给申请人所在单元的主管；`pkg try` 支持组织、多成员与审批；
新建子记录（请假、报销行）不再要求能改父记录（额度、报销单），宿主自己刷新汇总；审批搁置时父记录汇总能读到子记录的派生天数。

这一版的取舍：

- 请假天数按员工所在单元的组织日历数工作日（`workdays(fromdate, todate)`，含两端，扣周末与节假日），半天减 0.5；没有配日历时按周一到周五。
- 经理按“本单元同事”读（`team`），不按“本单元及以下”（`below`）：后者要记录上的组织单元字段与结构名，员工档案的部门字段接上组织之后再改。
- 报销单的“至少一笔费用”用公式字段 `items` 做条件，动作条件还不能直接对集合计数。
- 考勤与补卡放到 0.2.0。

## 这一版不做

薪资（单独的 payroll 包）、排班与轮班、设备打卡与定位、加班、借支与预支、招聘、绩效、入离职清单、按国家的法定假规则与自动发放额度。

## 验收

在夹具宿主装进空租户：人事建部门、员工与额度并配角色；员工请两天假，余额立刻少两天并显示“在批”；经理在收件箱批准，日历上出现；
员工超额申请被拒并说明还剩几天；员工忘打下班卡，提补卡，经理批准后考勤补齐；员工报销三笔，经理核减一笔后批准，财务付款；
员工看不到别人的申请，经理看不到别的部门。
