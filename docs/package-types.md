# 各类产品包设计规范

Platform 只有一种交付物：产品包（Package）。但不同业务定位的包在 `roots`、依赖关系、菜单呈现、角色边界与升级纪律上有三种典型形态。新建包前先确定自己属于哪一类。

## 一、三种包的定位与边界

| 形态 | 典型例子 | 是否有独立应用根（`kind: app`） | 依赖关系（`requires`） | 核心职责 |
|---|---|---|---|---|
| **1. 独立应用包（App Package）** | `crm`、`helpdesk`、`hr-core`、`assets` | 有（1 个或多个应用根） | 无，或仅依赖基础包 | 提供完整工作空间：菜单分组、看板/表格/日历、仪表盘、字典设置页、角色与自动化 |
| **2. 能力插件包（Plugin / Capability Package）** | 审批增强、外部连接器、合规审计动作、行业扩展字段 | **通常没有**（也可只提供管理配置页） | 依赖宿主核心或某个目标应用包 | 向已有对象贡献动作、视图、自动化流程、匹配规则或集成连接，不强行新增顶层导航 |
| **3. 共享基础包（Shared Core Package）** | `party`（往来单位/联系人）、`uom`（计量单位）、`catalog`（物料/产品） | 可有极简主数据入口，不含重业务流程 | 无（处于依赖树最底层） | 沉淀多应用共享的主数据对象、接口契约与具名查询，避免各应用各建一套客户或物料 |

## 二、独立应用包规范

1. **必须先有“一句话定位”与 `DESIGN.md`**：回答“用户打开它的第一秒做什么”，明确六词映射（状态、字典、动作、派生、角色、注意力）与受平台限制的取舍。
2. **生命周期与工作阶段分离**：不可逆或带必填信息的流转（赢单、丢单、解决、关闭、审批通过）必须用 `states` + `actions`；进行中的工作位置（待受理、处理中、等待客户、已升级）用字典对象做看板列，支持九色（`gray/blue/green/red/orange/purple/pink/amber/cyan`）与 `position` 排序。
3. **配置收纳进单一设置页**：所有字典对象收进主管角色独占的 `layout: settings` 菜单分组，禁止每个字典占一个一级菜单项。
4. **双角色起步、最小权限**：至少区分一线执行角色（本单元读写、不可归档、字典只读）与主管角色（全量读写、可归档、管理设置与发布）。安装本身永不自动授权。
5. **完整双语与图标**：有 `locales/zh-CN.yaml` 时覆盖 100% 界面文本；应用与每个对象选用互不重复的官方 Heroicons 名称。

## 三、能力插件包规范

1. **只增不侵**：通过包贡献向目标对象挂载动作、流程或连接，不要求修改目标应用包的源 YAML。
2. **退场无害**：插件退场（`drain`）与下线（`retire`）后，已产生的业务记录与操作历史必须完整保留，仅停用插件贡献的入口与动作。
3. **显式版本范围**：在 `package.yaml` 的 `requires` 写明兼容的目标包版本范围（如 `crm@^0.2.0`），不靠隐式字段猜测。

## 四、共享基础包规范

1. **严格向上兼容**：基础包被多个下游应用依赖，原则上只做向后兼容演进（新增可选字段、新增具名查询），避免破坏性改族（major bump）。
2. **严禁反向依赖**：基础包不得引用上层业务应用的对象或动作；上层应用之间通过基础包对象、对象接口或带版本的具名查询协作，禁止互相直接读写内部私密字段。
3. **所有成员可读**：`access` 写 `role: user` 就是租户里每个成员（平台的构建应用用户角色），装上依赖它的应用不用再另外授权；
   增改与归档另给本包的管理角色（`steward`）。
4. **应用怎样用**：`requires: [party@^0.1.0]`，引用字段 `ref: party.organization`；要加自己的字段就写附属对象：
   `extends: party.organization` 加必填引用字段 `base`，一个往来单位在一个应用里至多一条，建后不可改挂。
5. **参考记录的值与字段类型相符**：小数、整数写数字（`factor: 1000`，不要 `"1000"`），布尔写 `true`/`false`；不符时 `pkg` 指名拒绝。

## 五、通用验收门禁（所有包必过）

1. **静态校验**：`pkg lock <dir>` → `pkg check <dir>` 零报错（结构、图标、分类、译文、锁文件摘要全绿）。
2. **确定性构建**：连续两次 `pkg build` 输出 SHA-256 逐字节一致。
3. **内存租户探针（<10 秒）**：在内存租户中完成 `inspect → import → install`，跑通全部核心动作、派生公式、聚合汇总与边界流转（如重开、拒绝路径），手核每一条派生字段。
4. **空租户浏览器验收**：装进 `blank` 租户，走角色授权 → 核心业务主线 → 仪表盘核数 → 退场/下线/重装数据保留。
