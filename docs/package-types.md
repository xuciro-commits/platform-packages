# 包的种类

产品包是唯一的交付物。按它往平台里加了什么分四种；定义与判据以平台的 architecture“扩展”为准，这里写作者要遵守的规矩。
种类由 `pkg` 按包的内容推导、写进 `catalog.json`，作者不声明。`pkg check` 打印每个包的种类，并指名拒绝反向依赖。

## 一、四种包

| 种类 | 例子 | 判据 | 只能依赖 | 装上后在哪 |
|---|---|---|---|---|
| 应用包 | `crm`、`helpdesk`、`hr-core` | 有业务应用根（`kind: app`） | 主数据包、能力契约 | 应用轨与应用侧栏 |
| 主数据包 | `party`；`uom`、`geo`（参考数据） | 应用写 `surface: master-data`，或没有应用 | 别的主数据包 | “管理 → 主数据”；在应用里经引用字段选用 |
| 能力包 | `call/1`、`document.render/1` | 带能力契约或它的实现 | 契约、主数据包；不依赖应用包 | “管理 → 能力”里绑定；入口在声明了 `uses` 的应用里 |
| 扩展包 | 行业字段、审批增强 | 依赖某个应用包，只往它里面加东西 | 目标应用包（写版本范围） | 目标应用里；目标应用设置列出已装扩展 |

- 一个包贡献几层时按最高层算：自带一份契约的应用包仍是应用包。
- 依赖只能向下。主数据依赖应用、能力依赖应用，`pkg check` 指名拒绝。
- 组织（人、组织单元、岗位、内部地点、日历）属于平台，不做成包；要给人加字段，写附属对象 `extends: enterprise.element`。
- 每个类型都该有的（评论、附件、打印预览、条码）是平台特性，不做成包。
- 新建包前先回答：它是给某一个应用加东西（扩展），是多个应用共用的名词（主数据），是要能换供应商的能力（能力），还是一个业务场景（应用）。

## 二、应用包

1. **先有“一句话定位”与 `DESIGN.md`**：回答“用户打开它的第一秒做什么”，写明六词映射（状态、字典、动作、派生、角色、注意力）与受平台限制的取舍。
2. **生命周期与工作阶段分离**：不可逆或带必填信息的流转（赢单、丢单、解决、关闭、审批通过）用 `states` + `actions`；
   进行中的工作位置（待受理、处理中、等待客户、已升级）用字典对象做看板列，支持九色（`gray/blue/green/red/orange/purple/pink/amber/cyan`）与 `position` 排序。
3. **配置收进一个设置页**：所有字典对象收进主管角色独占的 `layout: settings` 菜单分组，不给每个字典一个一级菜单项。
4. **双角色起步、最小权限**：至少区分一线执行角色（本单元读写、不可归档、字典只读）与主管角色（全量读写、可归档、管理设置与发布）。安装本身永不自动授权。
5. **完整双语与图标**：有 `locales/zh-CN.yaml` 时覆盖全部界面文本；应用与每个对象选用互不重复的官方 Heroicons 名称。
6. **用能力，不自己实现**：打电话、渲染 PDF 这类要能换供应商的事，在动作上写 `uses: <契约>/<主版本>#<动作>`，绑定了入口才出现；不在包里直接接第三方。

## 三、主数据包

1. **严格向上兼容**：被多个应用依赖，只做向后兼容的演进（新增可选字段、新增具名查询），不轻易改族。preview 阶段经负责人同意可以破坏性升级。
2. **不反向依赖**：不得引用应用包的对象或动作；应用之间经主数据对象、对象接口或带版本的具名查询协作，不互相读写内部字段。
3. **所有成员可读**：`access` 写 `role: user` 就是租户里每个成员，装上依赖它的应用不用另外授权；增改与归档给本包的管理角色（`steward`）。
4. **应用怎样用**：`requires: [party@^0.1.0]`，引用字段 `ref: party.organization`；要加自己的字段就写附属对象：
   `extends: party.organization` 加必填引用字段 `base`，一个往来单位在一个应用里至多一条，建后不可改挂。
5. **参考记录的值与字段类型相符**：小数、整数写数字（`factor: 1000`，不要 `"1000"`），布尔写 `true`/`false`；不符时 `pkg` 指名拒绝。
6. **不进应用轨**：应用写 `surface: master-data`，它就只列在“管理 → 主数据”里；`steward` 等角色与设置菜单照常写在这个应用里。

## 四、能力包

1. **契约是独立资源**：放在 `contracts/`，标识 `<名字>/<主版本>`，写清动作、读取与事件；实现只写映射，`pkg` 按契约核对，不符就拒。
2. **不认识任何应用**：不依赖应用包，不往别的应用里加入口；入口由用到它的应用声明。
3. **装上不等于启用**：租户管理员在“管理 → 能力”里显式绑定实现；未绑定时用到它的入口不出现，调用答“能力未绑定”。
4. **换实现不改应用**：同一契约可以有声明式、连接器、沙箱代码或受管服务几种实现；契约升主版本才算不兼容。
5. **退场无害**：退场与下线后，已产生的业务记录与运行历史完整保留，只停用实现。

## 五、扩展包

1. **只增不侵**：经附属对象与贡献位往目标应用加字段、动作、流程或视图，不改目标应用包的源。与客户扩展是同一机制，区别是它随包交付。
2. **显式版本范围**：`requires` 写明兼容的目标版本（如 `crm@^0.2.0`），不靠猜字段。目标升级不兼容时，安装审阅指名阻止。
3. **退场无害**：退场（`drain`）与下线（`retire`）后，已产生的记录与操作历史完整保留，只停用扩展贡献的入口与动作。

## 六、通用验收门禁（所有包必过）

1. **静态校验**：`pkg lock <dir>` → `pkg check <dir>` 零报错（结构、图标、分类、译文、锁文件摘要全绿）。
2. **确定性构建**：连续两次 `pkg build` 输出 SHA-256 逐字节一致。
3. **内存租户探针（<10 秒）**：在内存租户中完成 `inspect → import → install`，跑通全部核心动作、派生公式、聚合汇总与边界流转（如重开、拒绝路径），手核每一条派生字段。
4. **空租户浏览器验收**：装进 `blank` 租户，走角色授权 → 核心业务主线 → 仪表盘核数 → 退场、下线、重装后数据保留。
