# W1：物料与库存独立业务设计（研究初稿）

状态：researched（仅下列源码片段），designed（候选边界）；尚未实现、未验收。基线见 plan.md。不要把本稿当正式包定义。

## 一句话定位
库管员打开库存，先知道什么物料在哪里、什么待处理、是否短缺；每次操作从可核查的业务单据产生移动事实，任何数量差异都能解释，不直接改余额。

## 目标边界与对象

候选 item-master 主数据：物料身份、分类、基础单位、启停；规格、批次策略、变体、单位换算政策逐项确认。已有 CRM 的产品对象与共享物料的重合必须先评审迁移/引用策略。候选 inventory 应用：库存位置、移动单及明细、移动事实、预留事实、盘点单及明细、余额投影。不要把这些名词直接当已确认的 AssetRef 或字段名。

| 权威事实 | 不变量 | 非权威投影 |
|---|---|---|
| 物料身份 | 唯一稳定标识；已过账不可任意改变计量语义 | 各应用显示标签 |
| 移动事实 | 接受后不可静默改写；调拨成对数量守恒；同请求不重复 | 实存数量、移动历史 |
| 预留事实 | 未释放的承诺有据可查；可用量不得重复承诺 | 可用数量、预计缺口 |
| 盘点事实 | 实盘量、时间、差异、原因和审批可追溯 | 待调整数量 |

## 六词与用户体验
状态：移动单草稿→已过账→已冲正；盘点草稿→提交→确认/拒绝→调整（具体状态待验证）。
字典：物料类别、位置类别、移动原因、盘点差异原因；数量单位共享 uom。
动作：收货、发料、调拨、预留/释放、盘点确认、冲正；将约束放在正式动作契约内。必须经 Platform 统一接受路径，禁止直接数据库改余额。
派生：实存量、已预留量、可用量、预计量分开；先验证精确数量和聚合能力。
角色：库管员录入与操作授权位置，主管确认/冲正，审计只读；不因有对象定义编辑权而授予库存操作权。
注意力：待收、待发、短缺、盘点差异和逾期预留；默认视图以待办和库存异常为先，列表可按位置/物料分组。正式封面建议为真实仓库货架与清晰物料标签，无品牌、4:3；item-master 封面建议独立的物料标识与规格样品场景。

## 最小验收（计划，尚未执行）
1. A 库位收 100 件；发 20；向 B 调拨 30；A=50、B=30、合计80。重复请求无第二次扣减。
2. 预留 A 库 40，发料竞争下只允许满足约束的请求成功；拒绝不得留下半张单或半条移动。释放后可用量恢复。
3. B 实盘 29，审批生成 -1 调整，冲正回 30；原历史可查，普通用户不能改事实。
4. 拒绝向分组/停用位置过账，拒绝跨租户引用和越权位置操作；拒绝非法/不精确换算，不能把数量存成不受控文本。
5. 无会计、采购、销售、制造包也能完成纯数量闭环；组合安装后验证每个外部请求有相关 ID、幂等与失败对账。财务计价未完成前不能标称完整成本核算。
6. 重启/重放后一致，升级保留事实与客户扩展；安装依赖合法、卸载预审无隐式删除。
7. 多明细录入和打印做真实用户验收；缺口未解决可以限定首版边界，但不得宣称已完整支持。
