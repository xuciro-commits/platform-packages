# B5 采购履约边界与研发顺序

来源：ERPNext 固定提交 8e10a348daaa93853de8c36dc55ec789a440c219。独立设计，非源码移植。矩阵新增12份来源对象的897条字段/布局、224处直接操作候选、29条权限记录；只有来源索引审计，未宣称逐项业务语义处置完成。报告、额外设置/供应商评分相关对象及继承、动态动作仍需补齐。

## 1. 采购收货与库存事实
- `purchase_order.py:879–927`：映射已提交订单及确切订单行，计算未收数量，筛选行并保留来源。
- `purchase_receipt.py:280–306,338–361`：日期、质检、前序订单、计量精度、供应商/公司/币种及来源明细一致性。
- `purchase_receipt.py:394–418,470–497`：提交、取消都改变前序状态、库存及财务事实；取消须实际补偿，不能只切换状态。
- 当前 inventory 有 movement/position/reservation/batch/serial 等对象，尚无采购收货对象。正式库存只由 inventory 的过账权威维护；purchasing 不复制仓库、库存余额或库存流水。来源订单尚不能正式批准（IB-ERP-0007），因此不得生成伪造已收货记录。

## 2. 采购发票、应付及付款
- `purchase_invoice.py:276–311,540–563`：前序订单、收货明细、供应商发票标识、应付科目、币种、精度和重复开票。
- `purchase_invoice.py:924–967,991–1010,1939–1964`：提交更新前序开票事实，按需库存过账、总账及应付；取消执行相反财务事实。
- 当前 accounting 只有导航占位，没有真实账户、凭证、应付及付款权威。禁止把商业金额字段当作应付余额；先设计会计基本模型，再实现发票与凭证。
- 发票、付款、税、汇率、财务期间与舍入规则应各自测试；不能默认一张采购单等于一张发票。

## 3. 组合契约
- 按 docs/package-types.md，独立应用不直接依赖其他应用内部对象；协作经主数据或具名版本化契约。已有 IB-ERP-0003，先验证现有动作 uses、能力绑定与可选缺失行为，尚不能断言平台缺少全部跨包执行能力。
- 建议采购确认以唯一来源订单行身份、基本单位数量和可追溯关联号为边界；库存接收入库、拒收及退回事实；财务确认发票和付款事实。重放、权限、累计数量、取消补偿、异常对账必须独立验收。
- 同一需求的累计采购数量应从唯一订单行事实计算，不能再造另一份订单量。需证明直接关联汇总、跨引用失效及并发写入的正确性。现有一报价一单只能防同一报价重复，不防同需求多报价重复占用。取消释放未设计完整，因此保持所有审批 fail-closed。
- 研发顺序：B4 累计数量与并发/回滚；B5 收货前置及来源行身份研究；库存契约单独探针；会计账户与凭证；发票与收货匹配；付款和报表。未通过真实事实验收前，仅允许明确标识的草稿或研究占位。
