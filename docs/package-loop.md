# PackageLoop — 通用研发质量控制器

执行主体：当前对话中的研究者直接完成研究、设计、实现、反省。控制器只执行确定性检查与数据整理，不启动任何模型或其他智能体。不安装常驻服务，不自动发布。

## 操作

    node scripts/package-loop.mjs freeze --project erpnext
    node scripts/package-loop.mjs run --project erpnext --resume
    node scripts/package-loop.mjs status --project erpnext
    node scripts/package-loop.mjs reflect --project erpnext
    node scripts/package-loop.mjs audit --project erpnext

run 复验正式包与研究证据；已通过则推进，失败则生成 next-task.md 并退出，等研究者直接修复后重新执行。不会自动调用任何 CLI 模型。冻结门禁变更须显式 --accept-changes 并复验。

## 自我优化与棘轮

每次检查归档原始结果；反省按固定问题类别聚类，不重复增加指令。reflection.json 保留累计次数、最多3个证据实例、最近4条相关结果和有限改进候选。已验证的控制器改进写入 loop/IMPROVEMENTS.md，修改控制器后独立回归。历史上下文压力触发单项研究批次和更短失败摘要。规则集合 loop/rules.json 最多10条、2600字节；冻结后数量和字节只能持平或下降，拒绝重复规则，语义冲突仍需人工审阅及行为回归。硬门禁由程序执行，不靠规则文字。

上下文简报最多12000 UTF-8字节，默认每次研究2项，压力下1项，最多4条相关证据及4条相关历史；原始日志和完整证据不删除。状态只保存最近32个事件，events.ndjson 持久化完整历史。此限制适用于控制器生成的简报，不代表能控制当前对话模型内部实际上下文。重复相同失败两次而没有验收进展时标记 review_required；不进行无效自动重试。

## 外层学习与产品完整性门禁

项目配置 quality 指向 coverage、evidence、productGates、capabilities、blockers。scope 与产品门禁、能力矩阵和阻塞清单由维护者冻结；evidence 是可追加的学习成果。study 任务按冻结 feature 列表收集原始 Git 提交中的源码行区间、用户意图、观察、设计、反例及未知项。程序检查结构、来源、范围及必填字段，只称 evidence_recorded，不宣称理解正确。关键未知项未关闭时不可判定产品就绪。产品门禁必须对应真实通过的实现任务，未绑定门禁保持 unverified；平台阻塞优先于测试通过。旧的最小业务探针仍可独立验收，但不代表产品完整。

    node scripts/package-loop.mjs audit --project erpnext

队列结束且产品范围未满足时为 product_scope_incomplete，不自动发版。当前外层基线是静态来源清单加人工冻结的产品维度，不是自动完整性证明；仍需补动态调用、异常场景、语义审阅、浏览器及跨包专项验证器。

## Safari 用户确认反馈桥

详见 [PackageLoop Safari Bridge](package-loop-safari.md)。仅投递有界任务草稿，用户确认发送，回执通过 MCP 写入本地账本；不读取网页模型输出，不启动常驻模型或自动提交。

冻结前校验固定 Git 提交的所有 coverage 主路径及 requiredAnchors。requiredAnchors 为特定研究项要求的补充源码，不是全局强行套用某一语言。控制器本身也进入冻结输入。

覆盖清单可声明 discovery 规则（固定仓库、锚定路径模式）。冻结校验反向检查匹配路径是否都被索引，防止仅验证已有清单而遗漏新版资源。归档资源与当前资源分开标记，保留迁移证据。

## 增量恢复与验收回执（PL-015）
冻结保留门禁签名未变的连续完成前缀；旧格式或公共控制器变更须复验。成功回执绑定任务、探针、冻结输入、完整 packages 树、platform.lock、验证器和环境指纹及原始日志哈希。失败不缓存。status/audit 区分历史与当前有效验收。run --max-steps N 限制新验收任务数；历史任务即使队列结束也复验；尝试或无进展超限进入 review_required；显式 --retry-review 可复核重启。recover 仅归档确认已退出的本项目锁，父或已记录子进程组存活则拒绝，不启动模型。

## PL-016 外部阻塞延期

队列任务可显式声明 defer: {reason, feedback}，feedback 必须对应配置 feedbackDir 中真实的 Inner-box ID 文件。延期是冻结输入，需维护者显式接受；它从 next 选择中排除，但不增加 completed，不删除原探针，也不解锁产品发布。status/audit 单独列出延期任务及反馈状态；队列可执行项耗尽仍以 deferred_tasks 阻塞结束。verify --task 可重测有探针的延期项，取消延期需要修改队列并重新冻结。后续仅排不依赖延期能力的研发切片；当前没有自动依赖推理。

## PL-017 完整页面与占位验收

来源侧栏逐项索引（含折叠组、子项、稳定顺序）：navigation-source-index.json。每个新包需建立导航契约，所有来源入口必须有实际页面资源、共享对象别名、平台内置Dashboard或明确只读占位；禁止伪造业务事实，禁止将占位计为产品通过。当前购买/库存制品已通过 scripts/package-navigation.mjs 比较固定源码与 pkg build 输出；每次关联任务验收前执行冻结的导航门禁，并绑定回执。实际折叠和无对象静态页面缺口关联 IB-ERP-0004；平面组与占位不是浏览器完成。

IR 试验 scripts/package-ir.mjs：结构化采购申请 IR 输出到独立预览目录，不覆盖 packages，支持字段、状态、权限、约束和简单转换动作，保留未解析项。尚未将 IR 迁移为正式权威；现行手写 YAML 仍为权威。

## PL-018 完整导航骨架

固定 ERPNext 来源12个侧栏（其中 portal 为空），11个非空模块全部通过制品逐项验收：276来源入口+45组=321条；另保留28补充业务入口和用户截图4个额外入口。235个占位含截图3项，不计业务完成。已存在的 CRM、资产、项目、客服保留原对象/动作/仪表盘/设置角色与原设置页，候选版本增加一位 patch，stage test；新增财务、销售、制造、质量、ERP设置同为 test。折叠与独立静态页面依赖 IB-ERP-0004，未做浏览器/全量安装/升级验收，不发布。freeze 从固定源重新核对侧栏文件及条目并拒绝缺失合同；所有11份导航合同纳入冻结门禁。20/20 Loop+IR+navigation专项回归通过。

## PL-019 细粒度字段与操作覆盖

## PL-022 研究元数据与业务验收解耦

批次说明与字段研究矩阵仍属于冻结输入，变更需显式 freeze --accept-changes，字段审计仍运行；仅对业务任务的回执签名排除这两类描述性文件，避免单纯研究记录变化导致已通过运行门禁被重复执行。执行器、探针、制品、工具链、环境及全包树仍参与签名；研究任务和全局门禁仍保守失效，历史已经清空的完成记录不恢复。新增专项测试验证冻结、回执复用及真实模型修改重新验收，23/23综合回归通过。
